# 평가 계획
갱신: 2026-09-23 · D0017~D0019 · 소유: B, 실행 도구는 C 협업

## 1. 먼저 확인할 것

모델 실험과 A 플랫폼 개발은 병행한다(D0018, model-lab.md). 모델 실험에 구매/판매 화면은 필요하지 않다. 실데이터 중앙 FL는 독립 검증 가능한 보호 모듈 G4 통과 후 실행한다. 그 전에도 데이터 분석·판매자 단독 학습·합성 FL는 가능하다. G2/G3는 서비스 통합 게이트이며 모든 모델 실험의 선행 조건이 아니다.

E-G0는 NLP와 텍스트만 기준선의 소형 실행이다. 입력 품질·상품 절단률·학습/추론 시간·메모리를 측정하여 모델과 실행 예산을 정한다. full dataset 속도는 추정값을 실측처럼 보고하지 않는다.

첫 예측 target은 다음 방문의 상품 집합이다. quantity나 H일 내 확률로 바꾸지 않는다. 카테고리 예측 전환은 상품 기준선의 품질·계산량을 본 뒤 팀 결정 기록으로 남긴다.

## 2. 시간 분할과 누출 방지

예제: 최소 3개의 과거 방문 → 다음 방문의 고유 상품 집합 Y. 입력 방문은 최근 L=10개. 방문 내 최대32개 절단은 입력에만 적용하고 Y는 자르지 않는다. 동일 장바구니의 일부 상품으로 나머지 상품을 예측하는 문제로 바꾸지 않는다.

**cutoff는 target의 순서 키이며 history는 key < cutoff다.** 직전 방문 키를 cutoff로 설정하지 않는다. 같은 시각의 장바구니는 ID로 안정 정렬한다. 정답 방문의 상품·관계는 입력에 없다.

| 출처 | 외부 분할 | history/관계 스냅샷 |
| --- | --- | --- |
| Dunnhumby | 기존 week 기준 train 2~39 / validation 40~43 / test 44~52. 밖의 행 처리 수를 보고 | history는 target의 (timestamp,basket_id) 미만. 관계는 해당 주 시작 이전 이벤트만 |
| Instacart | 고객별 prior 방문 순서, floor(0.7n)까지 train, floor(0.8n)까지 validation, 나머지 test | history는 target order_number 미만. 고객 사이 절대시간이 없어 아래 진행률 규칙 사용 |
| live | 평가용 별도 로그/합성 시나리오 | 서비스 as_of 이전 완료 이벤트 |

Dunnhumby 주 경계와 데이터 timezone을 어댑터 config에 고정한다. 최초 학습주 이전의 이벤트는 warm-up history에만 사용하고 평가 target에서 제외한다. 외부 train/validation/test 결과를 섞어 모델을 fit하지 않는다.

Instacart 관계 스냅샷의 첫 규칙: 고객 u의 target 순번 k, 전체 prior 길이 n_u에 대해 b=floor(10×(k-1)/n_u)/10. 같은 판매자의 각 고객 v에서 처음 floor(b×n_v)개 방문까지만 관계에 사용한다. 고객 u의 query history는 k-1까지 사용한다. b와 해당 cutoff를 cache key에 넣는다.

이는 **고객별 진행률을 맞춘 가상 replay**다. 실제 동시점 causal split이나 신규 상품 출시일을 복원했다고 주장하지 않는다. 각 단계에 허용된 prefix에서만 특징을 만들고, shared weights는 train만으로 학습한다. validation/test 구간의 이전 관측은 replay 특징으로만 사용한다. 필요시 train 관계를 고정하는 보수적 비교를 추가한다.

공통 확인: target basket 제외, cache snapshot 분리, train에 validation/test label 미사용, 앞선 방문 포함. 내부 train 검증 고객 9:1 seed에는 round_id를 넣지 않는다. 외부 validation은 모델 선택, test는 최종 보고에 쓴다.

원자료에 판매 가능 기간이 없으면 해당 판매자의 전체 관측 상품을 처음부터 카탈로그로 알려주는 가정을 명시한다. 이를 실제 등록/판매 가능 시점이라고 부르지 않는다.

## 3. 두 콜드스타트와 보조 분석

### 신규 판매자

A-0: 해당 판매자는 shared 학습에서 완전히 제외한다. 공통 모델을 내려받고 자기 상품 텍스트·로컬 과거 이력으로 추론한다. 로컬 가중치 갱신은 0회.
A-few: A-0의 같은 variant/base에서 query_proj와 scorer만 소수 로컬 step으로 파인튜닝한다(D0019). 앞부분은 고정하고 step·시간·사용한 로컬 prefix를 기록하며 test label로 적응하지 않는다. 이전 방문을 입력 이력으로 읽는 것과 그 방문으로 개인화 학습하는 것은 구분한다.

합성 G3에는 학습 판매자와 완전히 다른 상품 목록을 반드시 포함한다. 공개 데이터는 판매자 ID가 다르다는 것만으로 상품 의미가 다르다고 주장하지 않는다. 출처별 ID 중복/정규 텍스트 중복률을 따로 보고한다.

### 신상품

C-new: catalog에서 seed와 상품 ID 해시로 사전에 보류 상품을 정한다(시작 후보 10%). 텍스트는 이용 가능하지만 보류 상품은 모든 학습 예제의 양성·음성·입력 이력·관계에서 제외한다. 보류 상품만 있는 target은 학습에서 제외한다. 선택 기준에 test 구매량을 쓰지 않는다.

평가에서 보류 상품을 후보로 되돌리고 관계 0 분기를 사용한다. 통제 평가 동안 보류 상품의 이전 구매를 history/관계에 반영하지 않는다. 각 query에 보류 상품 정답이 있는 사례를 보고한다. 이는 **구매 이력을 인위적으로 보류한 실험**이며 자연 출시 시점 평가와 구분한다.

이 보류 규칙은 공통 학습뿐 아니라 개인화 학습의 양성·음성·이력·관계에도 동일하게 적용한다. 개인화 단계에서 보류 상품을 학습한 뒤 C-new라고 보고하지 않는다.

원자료에서 같은 상품이 여러 판매자에 있으면 전역 보류 집합을 사용한다. 각 출처 ID로 확인 가능한 중복은 차단하고, 출처 간 실제 동일 상품 여부를 확정할 수 없는 제한은 보고한다. “전 세계에서 처음 본 상품”으로 표현하지 않는다.

C-natural: 평가 cutoff 이전에 해당 판매자 구매가 0인 상품의 최초 구매 예제. 관계 0·학습 노출 여부를 기록한다. Instacart는 진행률 가정 아래의 관측 무이력 사례다. 데이터에 등록일이 없으면 출시 직후라고 부르지 않는다.

C0: 관계 특징만 0으로 가리는 보조 ablation. 이력·양성/음성 학습에서 이미 본 상품일 수 있으므로 신상품 성능의 증거로 쓰지 않는다.

## 4. 비교와 지표

필수 비교는 COMPARISON의 2×2다: T-G(텍스트 공통), R-G(관계 공통), T-P(텍스트 후반부 개인화), R-P(관계 후반부 개인화). 로컬 인기순은 sanity baseline으로 함께 보고한다. 상품 입력을 제외한 NLP·공통 모델 설계·후보·target·학습/개인화 예산을 맞춘다. 두 variant는 처음부터 독립 학습한다. 학습 후 l을 0으로 가린 C0로 텍스트 기준선을 대신하지 않는다.

관계 임베딩 효과는 T-G↔R-G와 T-P↔R-P, 개인화 효과는 같은 variant의 G↔P로 본다. T-G↔R-P만으로 관계 임베딩의 효과를 주장하지 않는다. 이 2×2는 FL의 우위까지 증명하지 않으므로, FL 효과를 주장하는 범위에는 같은 variant의 local_only 비교가 필수다. 같은 초기화·입력·후보·분할·학습 예산으로 비교한다.

하렉스 원본은 생성/매칭 방식이 다른 별도 모델이다. 이번 주 비교는 같은 점수화 구조의 text_only다. HAREX 재현 실험은 추가 범위로 표시한다. 고객 이력 없는 텍스트 유사도와 text_only 순차 모델을 혼동하지 않는다.

모든 방법은 같은 판매자의 같은 활성 후보를 점수화한다. 정답에 없고 이미 구매했던 상품도 후보에서 자동 제외하지 않는다. 재구매가 가능한 next_purchase 문제다. 샘플 음성 평가는 보조로만 쓰고 기본 ranking은 전체 로컬 후보다.

Recall@10/20, NDCG@10/20을 다음 방문의 고유 상품 집합에 대해 계산한다. 먼저 고객별, 다음 판매자별 평균을 내고 최종 판매자 macro 평균을 보고한다. 전체 예제 micro 평균도 별도 표기한다. 신상품 cohort는 전체 후보 ranking에서 보류 상품 정답에 대한 recall/NDCG와 유효 query 수를 함께 보고한다.

후보에 없는 정답·빈 후보·짧은 이력·빈 학습셋의 제외 수를 로컬 기록한다. 실제 데이터의 식별자/소수 집단 상세는 중앙 서비스에 보내지 않는다. 프로젝트 오프라인 보고에서도 개별 거래 대신 허용된 집계만 사용한다.

seed·roster·전처리/NLP/manifest 해시·split·학습 설정·최종 모델 버전·학습 참여 여부·관계 snapshot 정책을 실행 기록에 포함한다. 성능 향상은 측정 전 확정하지 않는다. 반복 seed 수와 예산은 E-G0 뒤 정하고 단일 실행이면 불확실성을 명시한다.

모델별 전체/학습 파라미터 수와 전처리·학습·개인화·추론 시간, 메모리·통신량도 기록한다. 같은 round/step 수를 같은 계산량으로 표현하지 않는다. 공통층 크기는 맞추지만 관계 모듈의 추가 용량은 비용과 함께 보고한다.

### 4.1 개인화의 공정성과 시점

개인화 lr/step cap/최소 데이터/검증 기준은 validation에서 정하고 두 variant에 같은 규칙으로 적용한다. validation/test 구간의 이전 관측을 특징으로 읽는 것은 허용된 replay 규칙에 따르되, 첫 정량 평가는 개인화 가중치를 사전 지정한 적응 prefix에서만 학습한 뒤 고정한다. 적응 prefix는 평가 target 이전이며 평가 label과 겹치지 않는다. 온라인 재적응 실험은 별도 protocol이다.

T-P/R-P가 준비되지 않은 이유와 비율을 보고한다. 둘 다 설치 가능한 동일 query 집합에서 paired P 비교를 하고 그 포함률을 함께 적는다. 한 모델에서 검증 실패한 사례만 몰래 빼거나 G를 P라고 채우지 않는다. 운영 정책(auto: 개인화 없으면 base)의 전체 결과는 별도 줄로 보고할 수 있다.

신규 판매자 A-0는 사전학습/공통 FL에도 포함하지 않는다. A-few는 두 variant에 동일한 로컬 적응 prefix를 제공한다. 개인화 실행 과정·판정·base/revision은 판매자 로컬 실험 기록에 남긴다.

### 4.2 서비스 시연과 성능 평가

성능 지표는 고정 test/replay로 측정한다. COMPARISON의 서비스 화면은 같은 feature snapshot/후보/시점에서 2×2 추천을 보여준다. 자유 사용에서 추천마다 달라진 후속 구매는 통제 실험의 정답으로 사용하지 않는다.

신상품 등록 → 같은 이벤트 replay → 관계 형성 과정을 보여주되, 거래가 생긴 뒤의 결과는 warm-up으로 구분한다. 순위 변화 여부 자체는 성능 지표가 아니다. 구매 반영, 개인화, FL 갱신의 효과를 별도 시나리오로 확인한다.

## 5. 실험 순서와 규모

**2주 실행 범위:** [팀 시작 안내](../team/start.md)에 따라 아래 R1/R2 전체 규모 실행은 후순위다. 두 출처를 포함하는 학습 가능한 소형 client 표본과 별도 보류 판매자를 사전에 고정하고, 동일 표본에서 두 variant의 2×2·local-only·신상품을 먼저 평가한다. 보호 참여 하한은 그대로 지킨다. client/행/상품 수·선택 규칙·seed·예산·제외 수를 기록하고 이를 소형 pilot으로 표시한다. 단일 seed 결과는 탐색 결과이며 전체 roster·전 업종·통계적 우위를 입증하지 않는다.

| 순서 | 구성 | 목적 |
| --- | --- | --- |
| E-G0 | 합성/소형 로컬 + 텍스트만 | NLP·계산량·입력 품질 확인 |
| G3/G4 | 합성 3판매자/보호 프로토콜 하한 | 연결과 보호 범위 검증 |
| R1 | Dunnhumby 101 + Instacart 100의 기존 roster | 이질 출처를 포함한 플랫폼 학습 |
| R2 | Dunnhumby 학습 → Instacart 보류 판매자 A-0/A-few | 미참여 판매자 이전 |
| 신상품 | 같은 분할에서 C-new, 필요하면 C-natural | 구매 무이력 상품 대응 |
| 선택 | 역방향 이전·Instacart only·관계 ablation·지각 이월 | 기본 결과 뒤 확장 |

R1/R2는 roster 규모이며 매 라운드 전원 동시 학습을 강제하지 않는다. C가 사전 선택한 cohort 전원 완료 또는 해당 라운드 전체 폐기 정책을 적용한다(CONTRACTS §6). 참여 수·deadline·누락·실제 완료 step을 기록한다. 실거래 중앙 FL는 G4 보호 경로만 쓴다.

첫 실행은 고정 라운드 수. 보호된 validation 합계/유효 수가 준비되면 조기 종료를 별도 도입한다. 개별 loss를 서버로 보내 구현을 편하게 만들지 않는다. 보호 집계의 양자화 오차와 평문 합성 평균 비교는 C가 G4에서 측정한다.

로컬 step cap/epoch cap/작은 데이터 때문에 소비 예제 수가 달라질 수 있다. 이번 기본 구현은 delta 균등 평균이며 추가 step 보정은 하지 않는다. 연구용 FedNova/지각 이월 규칙을 몰래 기본 경로로 되살리지 않는다.

관련 미확정 사항과 완료 증거는 [열린 구현 항목](open-questions.md)를 확인한다.
