# 현재 채택한 설계 결정

과거 논의 전체를 재게시하지 않고 현행 기준만 요약한다. 이는 설계 선택이며 성능·보호 검증 완료의 증거가 아니다. 상세는 연결된 설계 문서에 있다.

## D0017 · 판매자 로컬 서비스와 보호 FL

- 구매자·판매자 화면과 주문 이력은 판매자 origin/저장소에 두고 중앙은 공개 카탈로그·접속 위치·허용된 집계만 가진다.
- 예측은 상품 단위 next_purchase. 고정 상품 ID 출력행 대신 각 판매자의 후보 표현을 공통 함수로 점수화한다.
- 합성 연결 확인과 최종 보호 모드를 구분한다. 실거래 유래 개별 평문 delta/loss는 중앙에 전달하지 않는다. 공개 데이터의 실험실 시뮬레이션은 D0020을 따른다.
- 첫 FL는 고정 cohort 전원 완료 또는 전체 폐기, 균등 delta 평균이다. 추가 step 재스케일·지각 이월은 첫 범위에 없다.
- A는 플랫폼/주문, B는 데이터/NLP/모델, C는 계약/FL/보호/통합을 맡는다.

근거: 독립 데이터 보유 주체의 원자료를 공유하지 않으면서 공통 추천 함수를 학습하려는 목표다. 서로 다른 데이터셋이라는 사실만으로 FL 필요성이나 효과를 주장하지 않는다. [아키텍처](architecture.md), [인터페이스](interfaces.md).

## D0018 · 모델 실험과 서비스 시작 분리

B의 같은 모델·특징 core로 화면 없이 학습/평가/checkpoint 재개를 수행한다. C 집계 core도 HTTP와 분리한다. 검증한 모델을 초기 release로 설치하며 앱 startup에서 처음부터 학습하지 않는다.

관계 입력은 고객·바스켓·방향별 시간 정보를 유지한다. 시간 간격은 각 관측의 time_mlp 후 pooling한다. 간격을 평균/중앙값 하나로 먼저 줄이는 근사는 동일 설계가 아니다. 구체적인 이웃·시간쌍 예산은 소형 예제로 확정한다.

근거: 학습 비용을 서비스 기동과 분리하고, 모델 실험과 화면 개발을 병행한다. HAREX의 정확한 재현이나 HAREX 대비 성능 향상을 이미 입증했다고 표현하지 않는다. [독립 실험](model-lab.md), [모델](model.md).

## D0019 · 전체 공유 후 로컬 후반부 개인화

고정 NLP를 제외한 해당 variant의 전체 추천 가중치를 FL한다. 로컬 개인화는 공통 base 복사본의 query_proj/scorer만 학습한다. 관계 값과 개인화 결과는 로컬에 남고 관계 해석 MLP는 FL 공유에 포함된다.

text_only와 text_relation을 각각 학습하고 global/personalized를 비교한다. 관계 입력을 사후 제거한 결과로 text_only 학습을 대체하지 않는다. 두 모델의 같은 split·후보·예산을 맞추고 FL 이득은 같은 variant의 local-only와 별도로 비교한다. 새 base에 옛 개인화 tail을 붙이지 않는다.

근거: 파라미터별 임의 분할을 줄이면서 관계 입력과 개인화 효과를 나누어 검증한다. [비교](comparison.md), [평가](evaluation.md).

## D0020 · 실험실 FL 시뮬레이션과 서비스 보호 경로 분리

- 공개 데이터(Dunnhumby·Instacart)의 FL 실험은 **실험실 시뮬레이션**으로 수행할 수 있다. B 실행기가 한 프로세스에서 판매자별 데이터·optimizer·상태를 분리해 학습하고, C의 집계 core를 직접 호출해 같은 규칙(고정 cohort 전원 완료 또는 폐기, 균등 delta 평균)으로 합친다. HTTP·coordinator 서비스·판매자 서비스는 거치지 않는다.
- 이 결과는 "비보호 FL 시뮬레이션"으로 표시한다. 보호 집계를 했다고 쓰지 않는다. 실험실에서는 실험자가 원자료를 이미 모두 가지므로 보호 집계가 숨길 대상이 없다([아키텍처](architecture.md) §1).
- 서비스 경로는 바뀌지 않는다. 판매자 서비스의 FL은 G4 전에는 합성 평문만, G4 뒤에는 protected만 쓴다. 실험실 코드를 서비스 경로에서 호출하거나, 실데이터를 서비스의 synthetic_plaintext 경로에 연결하지 않는다.
- G4는 "보호 FL"이라고 쓰기 위한 조건이며 R1/R2 실험의 선행 조건이 아니다. G4를 통과하면 같은 실험을 보호 모듈로 다시 돌려 양자화 오차를 포함한 차이를 보고할 수 있다.
- 실험실 보고에는 공개 데이터의 판매자별 지표와 paired 통계를 쓸 수 있다. 개별 거래는 싣지 않는다. OQ10은 서비스 중앙이 받는 지표에만 해당한다.

근거: 정량 결과 전체가 가장 위험한 G4 뒤에 묶여 있었다. 그런데 실험실의 보호는 아무것도 숨기지 않으면서 결과만 막았다. 서비스 경로의 보호 원칙(D0017)은 그대로 둔다. [독립 실험](model-lab.md), [평가](evaluation.md).

## 초기 공통 코드에서 고정한 경계

PR #3은 공통 import·Protocol·dataclass·예외를 정하고, A lifespan이 판매자 runtime 하나를 만들고 C client에 같은 runtime/jobs를 주입하도록 했다. runtime은 동기 API, start/stop은 async이며 학습 작업은 판매자별 단일 background 실행기로 보낸다. worker는 판매자당 1개다.

이것은 연결 뼈대다. 영속 주문·실모델·FL 전송·보호 구현, 실제 트리거/복구는 [열린 항목](open-questions.md)에 남아 있다. 초기 코드로 해당 기능의 완료를 주장하지 않는다.
